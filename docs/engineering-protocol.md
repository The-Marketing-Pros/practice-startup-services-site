# Engineering protocol

Use isolated branches/checkouts and preserve existing architecture and unrelated work. Read this repository's developer handoff and relevant package/contract documents before editing. User instructions govern authorization; this protocol does not authorize merge, deployment, production migrations, external messaging, spending, access changes, or deleting repository content.

1. Keep changes small and coherent. Keep stacked PRs draft until prerequisites land; then retarget, verify the final diff and actual main ancestry (including squash merges), and rerun checks.
2. Test behavior and affected failure paths: authorization/tenant isolation, retries, concurrency, partial failures, migration compatibility and recovery with populated data. Inspect changed UI in loading, empty, error, permission and recovered states. Identify local, simulated, CI, preview and production observations separately.
3. Freeze implementation before independent review. Record real findings without a quota; reproduce supported defects, fix them, rerun affected checks and obtain another review of changed code. Missing, malformed or unavailable review stays incomplete. Use the adopted code-review-loop when available, within current source-transmission authorization. Do not transmit private source to an additional provider on the strength of another repository's approval.
4. Every PR includes the review-evidence section and a committed sanitized record under `docs/reviews/`. Use V1 for implementer verification, R1/R2 only for separately assigned independent reviews actually completed. For each channel and round record role/independence, requested model and actual reported model (or unavailable), date, exact head/base, scope, verdict, findings/dispositions, limitations, evidence digest and CI links. Auxiliary provider models, repeated calls and checklists are not additional independent reviewers. Later code changes make earlier verdicts historical. Evidence-only commits must be identified and inspected separately; never claim a receipt covers a SHA it did not review.
5. Audit combined main after every five newly integrated PRs using [the integration audit](integration-audit-protocol.md), before the next feature batch. An unmerged PR or merged badge on a different destination does not count as integrated source. Include **The eleventh thing** repeated-use assessment with concrete triggers and evidence.
6. Follow [repository governance](repository-governance.md). Andrew Eriksen (`@ppsonline`) is the sole human owner. Independent reviews may be performed by agents, including Iris, Alf or Charlie, and must be labeled as agent reviews with their actual identity and evidence. No second human reviewer is required. GitHub authors cannot approve their own PRs; use an eligible non-author agent review when a required approval is configured. Do not require CODEOWNERS approval from Andrew on a PR authored as `ppsonline`, invent another human gate, or use a routine bypass. Record Andrew's actual authorization separately from agent verification.
7. Use lockfiles and reviewed dependency update PRs; pin CI actions, minimize permissions and keep private evidence, credentials and customer data out of Git/logs. See [security guidance](../SECURITY.md). A successful vulnerability scan is a dated result, not a security certification.
8. Keep reproducible setup, supported behavior, architecture decisions and known production gaps current. Avoid speculative blockers, implementation-mirroring tests, cosmetic coverage targets and architecture rewrites merely to standardize.
